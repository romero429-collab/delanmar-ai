# Phase 0 — Baseline & Boundaries

**Status:** Not accepted. Maturity per [IMPLEMENTATION_STATUS.md](../IMPLEMENTATION_STATUS.md); completion is governed by [PHASE_ACCEPTANCE_STANDARD.md](../PHASE_ACCEPTANCE_STANDARD.md).

## Objective
Define scope, business workflows, owners and measurements.

## Required deliverables
- Select the first business workflow.
- Define its human owner and approval points.
- Establish baseline measurements.
- Separate platform capabilities from business-specific data.
- Define what is explicitly outside the pilot.

## Dependencies
None. This is the first active work package.

## Related business pilot stage
Pilot Phase 0 in the [OpenWorks pilot plan](../strategy/DELANMAR_OPENWORKS_PILOT_SETUP.md) (business track; numbering is not equivalent).

## Acceptance
- **Minimum maturity: Tested** by documented review of the baseline and boundary artifacts.
- Review a selected workflow with start and end points, named human owner, approval points, scope and exclusions.
- Review baseline measurements recorded before automation, including definitions, collection period and data sources, alongside the measurement plan, data access, retention and separation boundaries, and a permission plan identifying allowed, approval-required and prohibited actions.
- Verify the permission plan against representative permitted and prohibited actions; record authorization tests for any executable controls in scope, including denials.
- Record revision, environment, commands or procedure, results, limitations and reviewer; update the implementation status and obtain human-owner approval.

## Governing rule
No agent may exercise authority that the Rust Core has not explicitly granted.
